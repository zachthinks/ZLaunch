# Secure Items

A local Mac vault reached through the Secure Items launcher command. Names are
searchable only after unlock; values are hidden until explicitly revealed or
edited. Return copies, Command-N creates, Command-E edits, Command-Return saves,
and Escape leaves the editor. Delete asks first. All launcher themes use the same
native surface. This is deliberately not a JavaScript extension: extension form
state and LocalStorage are not a suitable secret-storage boundary.

## Invariants

- Data lives in a dedicated bundle-identifier-scoped data-protection Keychain item.
  Its encoded payload includes both names and values; attributes contain no item
  names. Synchronization is false, accessibility is when-unlocked/device-only,
  and the access control requires user presence. There is no plaintext fallback.
- Unlock uses macOS owner authentication and reuses its LAContext for Keychain
  operations. Swift code owns that context, never JavaScript. Blocking Keychain
  operations execute off the main actor. Authentication cancellation invalidates
  the context; generation checks reject late results. Pending writes serialize
  against later operations, and edits are frozen while a save is pending.
- A session locks after 120 seconds idle, on screen lock/sleep/session switch, when
  navigating to another feature, or at termination. Hide clears drafts and reveals.
  Hidden list sessions can remain unlocked until timeout when palette preservation
  is enabled. The app does not promise zeroization of Swift-managed memory.
- Copies (including editor selection copies) use currentHostOnly and concealed,
  transient, and autogenerated markers. ZLaunch's clipboard manager ignores the
  concealed/transient types. Clear after 30 seconds only while the change count
  still matches. Other software can read clipboard data while it is there.
- No secrets enter settings, backups, form state, extension storage, logs, files,
  URLs, or analytics. No autosave, automatic snippet expansion, or plaintext export.
- Data survives app updates under the same valid signing identity. It is NOT a
  portable backup: device-only Keychain records do not migrate to another device.
  Keep a recoverable original of irreplaceable secrets elsewhere.

## Signing prerequisite

This feature requires a provisioning profile authorizing the app-specific
Keychain access group. The entitlements resolve to
`FVY9AS28CU.com.zachthinks.zlaunch` for Release and
`FVY9AS28CU.com.zachthinks.zlaunch.dev` for Debug. Profiles and private signing
material must never be committed or copied into QA fixtures.

A Developer ID signature alone is insufficient. The main app target selects
`ZLaunch Developer ID` for Release and `ZLaunch Dev Developer ID` for Debug through
`PROVISIONING_PROFILE_SPECIFIER`; embedded helpers do not inherit these profiles.
Install the matching profile privately before signing. Hosted signing must also
install the matching profile privately before building. Unsigned builds may compile and exercise injected
repository tests, but cannot establish real protected Keychain success.

Do not publish until the signed bundle contains an authorized access group and
embedded profile, a synthetic item survives app restart/update, cancelled unlock
fails closed, and Dev cannot read Release items. See Apple's
[TN3137](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains.md)
and [access-group documentation](https://developer.apple.com/documentation/security/sharing-access-to-keychain-items-among-a-collection-of-apps.md).

## Validation

`SecureItemsTests` covers exact Unicode/multiline round trips, validation, sensitive
clipboard markers and ownership-based clearing on an isolated pasteboard.
`SecureItemsCoordinatorTests` injects authentication and a repository to cover
cancelled/late authentication, lock clearing, failed writes and draft protection.
Real Touch ID, signed Keychain writes, hardware sleep, and cross-device clipboard
behavior require separate runtime checks; unit tests do not establish those.

## Upstream maintenance

The feature implementation stays under `Features/SecureItems/`. Shared changes are
limited to command routing, palette modes/screens, editor key handling, lifecycle
ownership, localization, and app signing. It does not change extension runtime
semantics or introduce a separate launcher rendering path. During upstream merges,
review those integration points and rerun the existing feature harnesses. The
profiles remain private operational inputs; upstream signing workflows stay intact.
